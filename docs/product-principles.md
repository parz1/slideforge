# 产品理念

Slideforge 不是“输入一句话然后随机生成 PPT”的工具，而是一个面向固定范式和固定模板的 AI 演示稿生产工具。

它的核心用户不是喜欢在 PPT 里拖来拖去的人，而是已经有文案、讲稿、文章、课程材料、产品说明或销售话术，希望快速变成一套结构清楚、风格稳定、可继续编辑的演示稿的人。

一句话定位：

```text
用 LLM 把文案变成结构化演示稿，再用固定模板稳定生成可编辑、可审查、可预览的 PPT / Slidev。
```

## 核心判断

普通用户不应该写 Slidev 语法，也不应该理解 `v-click`、layout slot、Vue 组件或导出细节。Slidev 是渲染后端，不是用户界面。

M1 选择让用户写 `slides/*.md`，这里的 Markdown 是受 layout contract 约束的内容输入，不是直接暴露 Slidev Markdown。用户写的是“这一页要讲什么”，系统负责把它翻译成 renderer 需要的结构。

用户应该表达：

- 原始文案或素材是什么
- 这套演示稿要讲给谁
- 这套演示稿希望听众相信什么
- 每一页要表达什么结论
- 这一页想说明什么
- 希望用什么讲述节奏
- 是否需要图示、代码、对比、流程或结论

系统负责：

- 用 LLM 提炼大纲
- 拆分页面结构
- 选择模板
- 生成每页结构化内容
- 控制内容密度
- 生成动画策略
- 校验输出
- 渲染为 Slidev / PDF / PPT

## 用户工作流

Slideforge 的目标流程是：

```text
Source Copy
  -> LLM Planner
  -> Storyboard
  -> Deck Spec
  -> Template Renderer
  -> Preview / Export
```

用户可以从一段完整文案开始，也可以从大纲开始。AI 负责把素材拆成演示稿结构，模板负责把结构稳定渲染出来，编辑器负责让用户改大纲和当页内容。

用户主要编辑：

- 大纲顺序
- 当页标题
- 当页文案
- 表格、代码、指标、流程等结构化内容
- slide type
- speaker notes

用户不需要编辑：

- 绝对定位
- 低层级动画语法
- Slidev layout 语法
- Vue 组件代码

## 和普通 AI PPT 的区别

普通 AI PPT 倾向于一次性生成视觉结果。Slideforge 的输出链路是可审查的：

```text
输入文案
  -> Storyboard
  -> Deck Spec
  -> 模板校验
  -> Renderer
  -> 输出物
```

这样可以做到：

- 可复现：同一个 spec 和 theme 生成稳定结果
- 可审查：spec 可以进入 review 流程
- 可批量：同一模板可生成多套 deck
- 可治理：品牌、布局、动画由模板约束

## 非目标

- 不追求第一版生成最炫的 PPT。
- 不让 LLM 直接自由写最终 Slidev。
- 不做完整的自由拖拽式 PPT 编辑器。
- 不在第一版保证 PPTX 文本可编辑。
- 不把复杂模板能力暴露给普通用户。
